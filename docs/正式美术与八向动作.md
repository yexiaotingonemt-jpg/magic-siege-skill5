# 正式美术与八向动作

资源版本：`kc-final-20261027`。基于首轮场景4、兽人1与UI4选定方向，按KC成年比例、低噪点、克制魔法光效和古铜/深绿材质接入。

## 运行资源

目录为 `client/public/art/kc-final/`。五个职业使用独立的透明RGBA图集、同造型头像和20枚独立技能图标；场景使用完整宽度的新地面及64源像素的纵向接缝过渡。普通兵使用新增八向图集；防御塔与原有技能特效沿用现有资源。

每张运行图集1536×1024，8列×4行，每格192×256。列依次为S、SE、E、NE、N、NW、W、SW；行依次为待机、移动、普攻、通用施法。共160个方向动作格。

四个人形职业各使用正面、前斜、侧面、后斜、背面五个绘制方向，另外三个方向由左右镜像取得。悬浮战车使用四个动作姿态的整体平面旋转，炮口方向与选定方向一致。每个动作方向使用一张关键姿态，移动循环与出手过渡由模拟时钟驱动的网格变形、位移及技能特效衔接。

普通兵图集为 `minions-attack.png` 和 `minions-defense.png`，各1024×480、8列×3行，每格128×160；方向列与英雄相同，兵种行依次为近战、弩手、攻城炮。两军共48个方向格，每种造型使用五个绘制方向和三个镜像方向，保持身体直立；其中守方攻城炮资源预备保留，现行规则仍不生成守方攻城兵。普通兵每方向一张武器就绪姿态，原有程序网格动作控制步态、出手和收势。

2026-10-28弩手步行修正：兜帽弩手不再归入悬浮单位。两军新增 `arbalest-walk-attack.png`、`arbalest-walk-defense.png`，各1024×1280、8列×8行，每格128×160；行是S、SE、E、NE、N、NW、W、SW方向，列是一个周期的八个时间帧。每军64帧，两军128帧。以原造型为参考一次生成完整循环，再统一缩放、注册脚底；背面接触帧经逐帧复查重新排序，左右脚在半周期后交换前后位置。源提示词及归一化脚本保存在旁目录 `art-production/2026-10-28-walk/`。

`client/src/walk-animation.js` 按已有模拟时钟的1.1Hz相位选时间帧，仅在普通弩手状态为移动时播放。待机、准备、攻击、收势和控制仍选对应方向的静帧及原动作；英雄契约后使用英雄资源。走路图不再叠加腿部网格变形或整身悬浮，避免重复动作和脚部拉伸。暂停时相位与图集帧均冻结；透明轮廓命中使用当帧图像，Canvas与WebGL都可换帧。实机回归检查实际八帧播放、背面两只靴子的前后深度交换、暂停冻结和走路帧点选。

2026-10-28重甲近战兵步行修正：新增 `infantry-walk-attack.png` 与 `infantry-walk-defense.png`，格式同弩手走路图集，每军64帧（8方向×8时间帧）。近战兵采用0.9Hz周期，膝踝分别出现屈伸、过腿和落脚姿态；步行时停止整身跳动及程序网格拉腿。绘制后对同一军队所有方向和时间使用一个公共缩放，并注册头盔位置，避免大剑/盾牌边界变化让身体抖动。正背面接触帧在半周期后交换脚的前后关系。原图、步态参考、提示词和打包脚本保存在旁目录 `art-production/2026-10-28-melee-walk/`，图像使用内置生成工具制作。

客户端通过 `WALK_FILES`、`WALK_TEXTURES` 加载两种普通步行兵图集，`client/src/unit-art.js` 按兵种和阵营选择图集，仅在移动状态播放。新走路图集对应的 `client/src/melee-walk-layout.js` 保持近战兵显示高度约50像素；走路时只换UV帧、不再扭曲网格，暂停、攻击、控制和英雄契约继续使用各自状态规则。浏览器回归实际采集一个周期，验证八帧播放时局部网格及尺寸不变、两脚深度交换、暂停冻结和点选契约。

2026-10-27修正普通兵倒走：之前只有英雄调用八向逻辑，普通兵固定按阵营选正面图；现在所有受支持的移动单位统一经过 `client/src/unit-art.js` 选方向图、`client/src/unit-facing.js` 计算朝向。阵营只选造型，实际位移和出手目标决定方向。`client/src/minion-art-layout.js` 注册脚底、显示尺寸和变形区域。

`manifest.json` 记录格子、来源方式与动作顺序；`client/src/art-layout.js` 记录按身体而非武器范围测得的显示尺寸、脚底偏移与变形区域。五职业待机身体高度按64/62/70/70/68渲染像素校准；最终屏幕大小取决于游戏界面缩放。

## 朝向与动作规则

- 使用观察者视角下的八个屏幕方向，切换阵营视角时重新映射；文字、头像保持正向。
- 移动面向实际行进方向，方向边界有滞回区，微小坐标抖动不会反复换图；停下后保持最后朝向。
- 普攻在出手时面向攻击位置，并在本次出手和收势期间保持方向。
- 施法使用服务端已锁定的 `skillAnimation.from/to`，前摇中改变手选目标不会让已受理的动作改向；自体技能保留原朝向。
- 眩晕、冲锋、引导与技能继续使用已有动作优先级。画面不改变伤害、射程、费用、冷却、控制或服务端结算时机。
- 镜像方向同步镜像局部动作变形；点选继续使用当前方向图的透明轮廓及变形网格。姓名、状态和飘字共享更新后的血条基线。

## 主要接入点

- `client/src/art-catalog.js`：职业、技能图标行和方向动作格映射。
- `client/src/art-layout.js`：角色显示尺寸及动作区域。
- `client/src/unit-facing.js`：八向选择、视角映射与出手方向锁定。
- `client/src/renderer.js`、`client/src/unit-motion-view.js`：资源加载、动作关键姿态与网格动作。
- `client/src/main.js`、`client/src/skill-hud.js`、`client/src/kc-final.css`：头像、20技能图标及可适应尺寸的UI组件。

UI沿用640×1136布局与独立的施法、详情、加点触控区域，文字由程序排版。选定UI方向中的金边已收敛为低亮度古铜，绿色倒计时与金色奖励语义保留。

## 验证

`npm test` 包含图集覆盖、八向映射、出手锁定、方向防抖和原有战斗/命中检查。`npm run build` 生成可运行前端；浏览器验收覆盖五职业同局、契约、技能、重连及手机无英雄界面，另通过真实渲染图层验证普通兵在双方视角的行进朝向及背面轮廓点选。生成源稿、构图候选、打包脚本和QA截图留在项目旁的 `art-production/2026-10-27-final/`，运行只依赖仓库内最终资源。普通兵源图由内置图像生成工具生成，提示词保存在旁目录的 `sources/minion-prompts.json`。
