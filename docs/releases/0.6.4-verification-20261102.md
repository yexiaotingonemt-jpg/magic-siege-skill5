# 0.6.4 卡帧与动作停顿修复验收

本轮修复客户端显示层，服务器仍负责战斗状态和操作结算。两端统一发布0.6.4，战斗兼容0.6.0、协议3、运行schema2、账号schema1保持。计划使用保留战局热更，不清榜、不重开、不改动0.6.3被动、技能数值或积分公式。

## 已复现的问题与修复

1. 原位置插值结束后直接停住等新快照，150～550毫秒的抖动会使单位明显走走停停，即使平均FPS接近60。改为带速度连续性的插值和最多350毫秒的有界显示外推；施法、眩晕、引导、突进、暂停及异常速度分别限制，停止和瞬移不无限外推。权威坐标、技能判定与冷却时间不变。
2. 原渲染直接使用快照时钟，300毫秒后会冻结，且新数据到达可能改变动画时序。显示层改为独立单向校正时钟，最多领先最新快照650毫秒，暂停、倍速、后台恢复和换局可重置。战斗时钟和服务器对象不被显示视图改写。
3. 屏外单位也逐帧变形、投影，且Phaser自动preUpdate与手动preUpdate重复执行。改为仅更新视野及140像素安全边界内的单位，网格由一次手动投影更新；移回视野立即恢复。歩态采用实际显示移动检测。走路图集及零变形状态跳过无效逐顶点变形和临时对象创建。
4. 性能日志保留最长帧、P95与快照信息，另记录显示时钟停顿，避免只凭平均FPS判断是否流畅。该项不是GPU实际呈现或单位正常静止的测量。

## 对照场景与结果

同一台Windows电脑、Chrome headless、1440×1100、硬件WebGL：AMD Radeon RX 6600 LE / ANGLE D3D11。浏览器插件未提供，使用项目已有Playwright。隔离本地服务端固定180单位、20单位位于当前视野，重复150～550毫秒的快照到达间隔，预热后采集约10.5秒；额外以CDP模拟4倍CPU耗时，属于受控压力条件，不是普通机器的实测帧率承诺。

## 回归验证

- 全量604项逻辑测试：601通过、0失败、3项Linux专用在Windows跳过。
- 新增位置连续性、350毫秒外推上限、速度限制、施法/暂停/眩晕/瞬移、650毫秒时钟上限、换局和显示视图不改战斗状态的逻辑验证。
- 新增180单位真实浏览器抖动测试，检查屏外剔除、暂停冻结与移回视野。常规FPS正常时显示时钟停止也能被日志识别。
- 浏览器分组覆盖25个用例：五职业被动、清榜确认与双端权限、暂停、双方朝向、普通兵和五英雄八向八帧、冻结与停步、轮廓点选、友方/敌方目标交互及诊断。最终运动/性能9项与最终交互6项均通过。
- 屏外单位不再生成逐帧动画报告，原朝向测试改为分别将双方单位移入视野后检查；暂停测试等待渲染帧接收状态后再断言冻结，未删除动作或点选验证。
- 完整真实桌面包8项通过，覆盖原生仓库窗口、登录契约、会话、记住凭据、更新拦截和诊断权限；已准备0.6.4客户端预构建与启动清单。
