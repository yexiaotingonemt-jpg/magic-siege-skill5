# 0.6.2 NPC比例设置验收

客户端与服务端统一0.6.2，战斗兼容0.6.0、协议3；规则修订 `npc-ratio-wave-contract-20261031`。

## 功能

超级账号可在游戏区域外设置NPC补充模式，默认防守:进攻=1:3，支持自定义1～99整数比例或无NPC。权限读取服务端超级账号名单，对后续新增账号同样有效；客户端每10秒刷新授权状态。房主不能越权。

每次出兵后统计双方存活玩家与NPC英雄总数，只补充达到最小整数比例组所需人数，至少一组。优先契约正在交战的满血普通兵，其次后方满血兵；随机选择有合法兵源的职业，跳过玩家预选、受伤兵、精英和召唤单位。NPC合计最多99名，缺兵时等待后续出兵。已有NPC账号复用。

按用户确认，“无NPC”仅停止下一波及以后补充，现有NPC不删除，继续战斗至正常死亡。策略随重建战场、重开本局和兼容热更保留；完整服务进程重启恢复默认1:3。旧版保留战局热更不立即补兵，到下一波开始执行。

同时修复独立桌面打包漏带 `shared/performance-permission.js` 导致无法打开窗口的问题；原生仓库启动器复用，源码和预构建资源一同更新。

## 验证结果

- 完整逻辑测试587项：584通过、0失败、3项Linux专用按Windows平台跳过。
- NPC专项15项覆盖真人计数、随机职业、前线优先、无NPC保留现有英雄、延后生效、99名上限、200波账号复用、新授权与撤销、非法参数和旧入口绕过。
- 最终浏览器41项均通过（整套39项通过，修正上版友军靠近测试的旧断言后，另复测两种尺寸的目标交互2项通过）。其中新增双账号NPC设置2项覆盖桌面1440与窄屏390，验证SSE同步及无需重登的未来授权/撤销。
- 完整真实桌面包8项均通过，包括原生仓库入口可见窗口、登录契约、退出与重启会话、记住凭据、强制拉取提示、性能诊断权限与落盘。
- 热更及NPC复核32项：29通过、3项Linux专用跳过。模拟旧内存没有NPC策略，确认升级后仅补上默认策略、不删除或重建现有英雄，并保留成长、冷却、积分、待执行回调和会话。

旧浏览器测试改为明确选择普通兵和统计真人英雄；排行双人夹具显式关闭NPC并重建，避免自动NPC贡献混入人工样本。友军目标交互夹具按0.6.1已发布规则验证“先靠近，再按警戒范围索敌”，不再断言直接继承友军的敌方目标。
