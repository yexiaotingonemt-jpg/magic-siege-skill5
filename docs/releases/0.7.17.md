# 0.7.17：修复战局同步卡顿

## 原因与改动

客户端性能日志显示渲染稳定在约60 FPS，但网络快照最长间隔2.29秒，约10分钟内显示时钟累计停顿45.6秒。服务器CPU、内存无满载，公网长连接存在发送积压和TCP重传。原同步虽然启用了流式Gzip，仍每200毫秒重发完整单位、玩家、历史战报与服务器结算账本；多客户端共享有限出口时，状态到达速度落后于战斗推进。

- 显示快照排除结算账本、服务端记账字段、已过期减益与攻速状态，保留有效状态和有限额度判定。显示坐标精确到0.001格，不改权威坐标、战斗或技能计算。
- 客户端通过`delta=1`选择差量同步：首次、配置更新、换局和重新连接使用完整基准，后续只发送变动字段、增删实体及其顺序。未选择差量的连接继续接收全量快照，HTTP状态接口仍返回完整显示状态。
- 每条连接单独跟踪最后排入发送队列的基准；背压跳帧后，从该基准直接补发最新状态，暂停也不漏发。客户端独立保存网络基准，渲染插值和职业预选不污染它；缺少基准时重连恢复。
- 只改变显示和传输，游戏兼容版本0.7.0、协议3、战局schema3、账号schema1不变；新传输是可选扩展，保留全量接口。正式发布两端统一升至0.7.17。

## 验证

同一组正式服自然战斗的88帧、47～65单位快照，以相同Gzip参数逐帧flush比较：稳态平均16.371→1.249 KiB/帧，减少92.37%；按5Hz换算81.856→6.245 KiB/秒/客户端。88帧还原结果全部与裁剪后的完整状态一致。该对照固定战斗输入，不将场上人数变化当作优化收益；数值不含TCP头与重传。

- 904项单元、HTTP和热更检查通过，3项Linux专用检查在Windows跳过。
- 22项浏览器检查通过，覆盖五职业桌面/窄屏、双客户端契约与断线重连、个人飘字、性能诊断和版本门禁。
- 8项真实桌面检查通过，覆盖仓库启动器、契约、升级、重启会话、凭据、版本门禁和性能记录权限。
- 0.7.16→0.7.17保留战局及回滚预演通过：单位、玩家、英雄、资源、计时和已排队技能引用保持，进程引导层未修改。

集成主分支黑暗领主改动后重新验证：912项单元/HTTP/热更检查通过、3项平台检查跳过；18项关键浏览器检查通过。`npm run test:balance`的既有旧规则基准标准组通过，仍有19组策略顺序、1组中频总分优势及4组高频单技能超出中频总分的未达项；该入口不覆盖当前五职业设计的完整平衡验收，本任务不据此调整计分或宣称数值已全面平衡。
