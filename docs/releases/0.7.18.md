# 0.7.18：补齐完整状态HTTP响应压缩

0.7.17已将自然战斗快照的Gzip稳态流量降低92.37%，恢复约5Hz同步。正式桌面窗口60秒采样为59.94 FPS、网络P95间隔206.7毫秒，但两个诊断连接同时读取完整HTTP状态时，仍出现一次约1秒的同步间隔和400.6毫秒显示时钟停顿。原因是`/api/state`等JSON响应未协商压缩，大响应仍会与实时快照争用同一出口。

0.7.18对至少1024字符的JSON响应按`Accept-Encoding`协商Gzip；不支持或明确拒绝Gzip时继续返回原文，小响应不压缩。身份、配置、状态、错误语义和HTTP状态码保持一致，本地代理继续透传编码。回归逐项核对压缩与未压缩状态一致、编码协商和取消压缩，随后实测多人读取状态时的同步与显示时钟。

继承[0.7.17差量同步修复](0.7.17.md)。两端统一0.7.18，战斗兼容0.7.0、协议3、战局schema3、账号schema1不变；保留当前进程、账号会话和战局。最终公网、桌面与版本一致性验收另行记录。
