## 2. 问题清单与复现

### P2-01：亡灵护卫出生生命5%，但生命上限仍为8%

- **复现**：40级领主取得L16，开启君临并击杀一个敌人，读取护卫生命；再对护卫治疗。
- **预期**：规则写明护卫生命为领主最大生命5%，出生满血，治疗不能突破该上限。
- **实际**：领主最大生命128160；护卫出生 `6408 / 10252.8`，只有62.5%血，治疗后达到10252.8。完整治疗使护卫生命比5%方案高60%。
- **影响**：外观误示受伤；治疗使已经约束过的百分比派生回到8%，改变密集战斗的护卫存活与承伤。
- **定位**：原 `shared/trait-effects.js` 的 `onKill`，`hp=.05*maxHp` 与 `maxHp=.08*maxHp` 不一致。
- **证据**：`baseline/evidence/independent-v050/model-probes.json` 前两项；重跑该目录的 `model-probes.mjs`。
- **当前修正**：主开发已将上限改为5%；独立复测得到 `6408 / 6408`，治疗后仍6408。旧包保留原问题。

### P2-02：额外烙印的死亡爆炸60%，卡片与规则原文写200%

- **复现**：火法取得F11与F12，对主目标及其旁边目标施加烙印；杀死额外标记目标，读取另一名附近敌人承受的爆炸伤害，排除其他伤害与易伤。
- **预期**：原F12卡片及规则写“标记目标死亡产生200%攻击爆炸”，未说明额外标记降低。
- **实际**：施法攻击538.9时，额外标记爆炸造成323.34，即60%攻击；200%应为1077.8。主目标爆炸仍为200%。
- **影响**：玩家按文字判断的额外标记爆炸强度高于实结算约3.33倍，影响选卡取舍。
- **定位**：`shared/skill5-mechanics.js` 保存 `soulMarks.scale=.3`；`shared/trait-effects.js/onUnitDeath` 再将爆炸乘该倍率。
- **证据**：上述 `model-probes.json` 的F12项及 `draft-desktop-gold.png`、`draft-mobile-three.png` 的旧卡片文字。
- **当前修正**：主开发保留额外目标独立倍率，将F11/F12及规则明确为主标记200%、额外标记60%。独立确认新文本与原实结算一致；这是文本/规则修正，未提升该爆炸伤害。旧包仍显示旧文案。

### P2-03：阵亡后预览其他职业，待选卡可见但选择被服务端拒绝

- **复现**：账号此前玩过精灵并留下待选E01；阵亡后当前服务端职业为兽人。点击己方远程兵，在契约弹窗预览森林精灵，点击自动弹出的E01。
- **预期**：界面既已展示该职业保留的待选，就应选择成功，或明确要求先契约再显示选择。
- **实际**：客户端预览职业为5，服务端仍为0；点击后提示“词条选择已变化，请选择当前候选”，E01次数保持0。先稍后选择、契约精灵，再选可以恢复，无词条损失。
- **影响**：正常跨职业返场路径出现无法完成的选择，错误提示又误导玩家以为候选已变化。
- **定位**：原 `client/src/trait-draft.js/select` 未发送职业；`server/room.mjs`、`shared/simulation.js` 和 `shared/traits.js` 按服务器当前职业处理。
- **证据**：`ui-playthrough.json` 的 `cross-class pending before contract`，截图 [原候选拒绝](../../evidence/independent-v050/cross-class-pending-rejected.png)。
- **当前修正**：主开发增加明确职业参数并验证阵营及存活英雄限制。独立API复测：待契约精灵选择成功，兽人当前职业不被更改；伪造防守职业仍拒绝。更新后真实浏览器专项5/5通过，包含该路径。旧包缺少职业参数。

### P2-04：E17完整反击触发可无限存储到后续施法

- **性质**：原“每次技能最多3次”本身未被突破；问题是超限及无目标时的完整触发继续储存，缺少跨次缓存边界，形成数值与规则风险。
- **复现**：精灵取得E17，测试攻击快照100，每次阈值2000。一次直接有效治疗15000；接着下一次技能只产生1点有效治疗。
- **实际**：第一次触发3次、造成300伤害后仍存9000；第二次仅治疗1点，又造成300反击伤害。若第一次没有10格内敌人，则存15000，敌人进场后1点治疗即可释放3次。原逻辑没有完整触发缓存上限。
- **预期边界**：每次施法上限应配合明确的跨次进度规则；已达上限/无合法敌人的完整触发不应无限蓄积后集中释放。若设计保留缓存，必须公开其上限与释放条件。
- **影响**：后排或无敌人时可预存反击，后续微量治疗触发爆发；密集有效群疗的收益可能与当前技能投入脱节。过量治疗、护盾及共享治疗未混入该计数。
- **定位**：原 `shared/trait-effects.js/afterHeal` 在达3次或无敌人后退出循环，未处理剩余完整阈值。
- **证据**：`runtime-audit.json/e17`，分别记录有敌人与无敌人两种结果。
- **当前修正**：主开发仅保留不足一阈值的进度，并补充文案。独立复测两种情况都剩1000，下一次治疗1点不反击。旧包仍有缓存行为。

## 4. 阵容、成长和手动操作的数值风险

独立扩展为816组：4种进攻职业的全部1/2/3人重复组合共34阵容，等级1/10/40，种子3/71，四种控制条件（双方自动、仅进攻策略输入、仅领主策略输入、双方策略输入）。使用实际39次选卡形成40级构筑；同一比较固定构筑、关闭后续经验增长。无兵线、塔援，1000体力，最多180秒。

“策略输入”由脚本每0.25秒进行合法目标及技能优先级选择，不是人类对局胜率。与真实界面操作分开记录。原始结果：`baseline/evidence/independent-v050/composition-audit.json`。

| 40级阵容对1领主 | 双方自动的击杀/结果 | 仅进攻策略输入、领主自动 | 仅领主策略输入、进攻自动 |
|---|---|---|---|
| 双火法 | 18.45—24.45秒击杀领主 | 10.40秒，双火法存活 | 16.65秒进攻全灭，领主剩75.1%—75.9% |
| 兽人+火法 | 33.55—54.10秒击杀领主 | 20.40—21.40秒，二人存活 | 47.15秒进攻全灭，领主剩61.3%—70.6% |
| 兽人+战车 | 60.40—65.05秒进攻全灭 | 39.65—40.15秒进攻全灭 | 47.15秒进攻全灭 |
| 兽人+火法+精灵 | 24.45—27.45秒击杀领主 | 20.40秒击杀领主 | 57.85秒进攻全灭；双方均策略输入则25.40秒领主阵亡 |
| 三战车 | 21.45—23.45秒击杀领主 | 8.05—10.05秒击杀领主 | 12.10—12.50秒进攻全灭，领主剩93.5%—97.0% |

由此不能依据原36组自动战斗断言平衡。领主开免疫/火盾的时机和进攻爆发配合足以翻转结果；三战车后期对操作策略极敏感。建议后续用相同阵容、相同构筑、同一领主玩家做有兵线/塔援的交叉操作测试，避免直接按这个小样本砍倍率。精灵组合的长期收益和兽人承伤时间有价值，纯战车面对手动突进风险较高。

另做默认兵线、4进攻机器人/2领主、100初始体力且不补充的900秒样本：首批5级61.60—79.30秒、10级125.45—169.85秒；最终体力都为0，等级15—17，未达到20级。这符合本轮“不保证100体力完成40级”的规则，属于体验风险：常规体验很难看到后两次金色，必须通过补充体力继续，不能把40级全金作为普通单局必然体验。
