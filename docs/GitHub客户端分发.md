# GitHub 拉取后直接启动

## 同事使用

1. 使用 GitHub Desktop 或 Git 完整克隆仓库。以后更新时先退出游戏，再拉取最新内容。
2. 双击仓库根目录的 `魔法王座.exe`，或运行 `Start.cmd`。
3. 首次启动会自动展开本机运行环境。无需安装开发工具、Node.js、npm 或 Go。
4. 登录现有账号，连接正式服务器。窗口标题显示实际客户端版本。

必须拉取完整仓库。根目录 EXE 是约 3 MB 的启动入口，依赖仓库中的 `desktop-client.json`、`desktop-runtime`、`client/prebuilt` 和已有美术，不应单独拷贝该入口给没有仓库的人。没有仓库的同事可使用完整桌面客户端发布包。

## 本机位置与更新

- 固定运行环境首次以约 158 MB 的四个分片随 Git 拉取，后续版本复用；仅在升级 Electron 运行环境时新增对应运行环境版本。
- 展开的运行环境默认位于 仓库内被 Git 忽略的 `.desktop-cache/repository-client`，缓存不进入提交，仓库仍可直接拉取。
- 页面使用已提交的 `client/prebuilt`，美术使用已有 `client/public/art`，不重复打进一份完整桌面包。
- 账号和登录资料仍放在独立的用户目录；`%APPDATA%/Magic Siege/repository-source.json` 只记录本机仓库位置，不存账号密码。
- 客户端发现正式服要求的版本不一致时，禁止进入游戏并提示退出后手动拉取最新版。不会自动下载、安装、重启或切换到其他本机版本。
- 只更新源码、不更新配套的预构建内容不算正式发布。源码开发入口仍使用原有 npm 开发命令。

## 发布者流程

1. 遵守[统一版本约定](版本发布约定.md)，同步提升客户端、服务器和 package/lockfile 发布号。
2. 运行单元测试、构建并生成完整桌面客户端：`npm run package:client`。
3. 运行 `npm run package:repository -- <本次完整桌面包目录>`。发布者需要本机 Go 编译器；同事运行生成的 EXE 不需要。
4. 提交根目录 `魔法王座.exe`、`desktop-client.json`、`client/prebuilt` 和首次新增的 `desktop-runtime`。已有运行环境分片保持不可变。
5. 先将可直接运行的完整仓库通过 PR 合入 GitHub 发布分支，再从同一提交生成和部署同版本服务端；不再签名或上传自动更新包。验证旧版被拦截和拉取后新版登录。
6. 完整桌面 ZIP 可以附在私有仓库的 GitHub Release 中；仓库成员登录后可下载。不要把令牌、私钥、账号库或个人缓存放进仓库或 Release。

预构建清单记录入口、页面和桌面代码的校验值；运行环境分片及合并 ZIP 分别校验 SHA-256。客户端只接受与正式服发布号和兼容标记一致的本机仓库版本。
