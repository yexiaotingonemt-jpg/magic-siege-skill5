# 新版技能开发配置

来源为2026年10月31日钉钉当前六个分页。已实现五职业20技能和104条有效词条，数值状态为**待平衡**。未导入另一个聊天里持续变化的试算候选，也未发布到正式服。

## 启用与调参

在仓库根目录运行 `npm run start:design`，启动新版规则API，默认端口5185，默认账号数据保存在 `E:/Codex/Support/魔法王座/scratch/current-design-preview/data`。可通过 `PORT` 和 `KC_DATA_DIR` 环境变量覆盖。

另开终端启动本地客户端：

```powershell
$env:MAGIC_SERVER_URL='http://127.0.0.1:5185'
npm run dev
```

打开终端显示的本地地址。常规 `npm start` 继续使用原规则，便于与新版并行核对。切换规则须新建战局，旧词条ID不自动转换；不会将实验的60秒英雄更替或18点每分钟预算变成线上强制死亡或扣费。

默认参数在 [current-design-data.js](../shared/current-design-data.js) 的 `CURRENT_DESIGN`：

| 字段 | 内容 |
|---|---|
| `heroes` | 职业0级面板、每级生命与攻击成长 |
| `skills` | 五职业四技能基础效果、费用、CD、时间、目标数与距离 |
| `affixes` | 104个效果的职业实例、各档值、相对基础的基准、上限与品质 |
| `qualityWeights` | 全职业统一的蓝紫金抽取权重 |
| `rules` | 炙热、职业被动、战车分担、召唤、成长与计分常量 |
| `scoreCoefficients` | 钉钉当前职业系数；本次未重新拟合 |

职业编号沿用现有引擎：兽人0、战车2、领主3、火法4、精灵5。领主新版顺序是震荡、尖刺、冲锋、君临。

也可以把 `CURRENT_DESIGN` 对象另存为JSON，在启动时传入 `node server/index.mjs --design-config=E:/Codex/Support/魔法王座/outputs/design.json`；文件也可为含 `design` 的完整游戏配置。读取时检查有限数值、费用、目标数量、比例、档位和40次预算。不得用不完整试算文件直接替代完整设计配置。

词条 `values[rank-1]` 为该档效果绝对值，`baseline` 为取稿时的基础值。实际增量为 `values-baseline`，应用到当前基础技能；各档不逐档相加。修改基础技能会保留已设词条增量。修改词条可同时更新 `values` 与 `baseline`，但不能将差异值再次当成绝对值导入。

数值编辑器只编辑数值，保留描述、标识及布尔开关。技能说明、词条档值、费用与KDA使用同一份服务器配置；技能施放时保存攻击力、技能参数和词条快照。已有持续效果按原快照结算。基础面板的生命、射程、速度和攻速在下次契约生效；更改配置后应使用新战局重新验证，不能混用旧统计。

## 已实现的机制

- 四技能0级可用，每3点实际施法体力升1级，40级封顶；契约、击杀和塔伤不提供成长经验。全部主动、被动和通用词条共享每级一次的升级机会。
- 品质先抽取统一权重，再从该品质未满档的合法池抽候选；满档品质退出当前可选池。`inverseQualityWeights` 可用已校准的总体平均收益生成倒数权重。
- 兽人按缺血获得减伤，汲血引导、战吼保护与反弹、按被救友军缺血提供救援减伤、真实承伤蓄盾与不死。
- 火法炙热逐层衰减，同时影响攻速和受疗；标记无前置耗热或即时伤害，实际攻击命中触发附伤与获热；火球多目标／贯穿，天火按消耗层数增伤、返热及斩杀。
- 精灵按有效伤害／治疗转化，派生不递归；链接治疗共享与伤害平摊；净化按成功移除数量治疗；群疗持续吟唱、过量转盾与额外治疗转伤。
- 战车先求多目标合计效果再均分，包含伤害、减益与位移；腐蚀弹即时比例伤害、单次减疗、概率持续腐蚀／追加攻击；冰霜无需腐蚀前置；震荡按实际位移追加伤害，连轰固定落点逐炮叠加。
- 领主固有击杀恢复、随机单状态净化／驱散；尖刺按攻击者当前攻击反伤，冲锋晕眩与拖拽，君临免疫、范围伤害、吸血和召唤；反伤及召唤保留施法者归属。
- 新版 `B=a(D+M)+bT+cH+200K+100A`，`P=100S+B`，`KDA=B/max(S,21)`；服务器快照携带KDA，排行榜不再用总分／体力覆盖新版结果。窗口随实际统计累计，不用周期KDA均值冒充汇总。

## 验证与未定项

`npm run test:design` 检查结算、成长、配置和客户端说明；`npm test` 做全量逻辑回归；`npm run build` 构建客户端。

这次实现不调平衡。钉钉现有40秒大招CD、小数秒与零碎百分比原样保留，尚未符合新版整秒／CD目标；不在运行时粗暴取整。概率尚无最终总体平均收益，当前蓝紫金使用等权开发占位，明确不作为最终概率。整数秒、品质跨度、2倍技能效率、18点实际施法、1∶3五分钟焦灼、约3倍生存及KDA公平，仍需在本引擎中另行验收。

精英奖励的持续时间、随机奖励池和强效果额外解锁条件仍待定，本次不自行定稿。实验输出统一存放 `E:/Codex/Support/魔法王座`。项目原 `npm run test:balance` 仍测试旧规则、旧调度与KDA口径，报告不能当作新版已通过的证据。
