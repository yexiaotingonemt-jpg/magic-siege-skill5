# 可复算基准及适用范围

从仓库根目录运行：

```powershell
npm run test:balance
# 可指定另一个辅助输出目录，避免并行任务覆盖：
npm run test:balance -- --out E:/Codex/Support/魔法王座/outputs/本次技能调整
```

永久测试入口为 `tests/score-balance.bench.mjs`，不是历史报告的线性重计价。输出 `balance.json` 和 `balance.md`，包含当前系数、配置、每次施法次数、实际体力、分值分解和三策略差异，不依赖本机历史报告或绝对源码路径。

## 受控输入

- 5/20/40级固定，不在实验中升级。60秒包括一次契约，技能使用当前实现和费用；不补满窗口末尾尚未落地/结算的效果。
- 中频最多8/3/2/1次，间隔调度后仍检查真实前摇、冷却、目标和射程。优先尝试4→3→2→1，这是固定策略，不代表最优调度。
- 对手1英雄+3名4000血小兵，死亡补充；进攻面对领主，领主面对战士。英雄/清兵优先分别检查。
- 4名友方小兵各每秒攻击敌英雄100伤害，每秒流失200生命（最低1），初始1000/4000生命；每10秒添加8秒可净化减速，提供治疗、支援助攻及净化机会。
- 原始来伤：战士/领主每60秒自身满血1倍，后排0.25倍，均匀施加。无玩家归属的外部治疗维持存活，不给玩家积分；敌人关闭自主攻击。固定暴露用于检查积分结构，会弱化防护对延长寿命的价值，不代表实战防护无用。
- 无词条及一套种子987654的合法词条样本；每次真实候选选择首项。不同策略使用同一构筑，不为单技能重抽。该单样本不代表词条全分布。
- 三策略中①消耗当前实际契约体力；②四个单技能各按中频对应次数测试，选最终KDA最高者；③完整中频。另独立测试高频单技能（尽可能按冷却释放），再次四选一。

改技能会改变目标、缺血需求或有效命中时，应合理扩展场景并明示；保留旧基线作可比对照，不为追求通过而临时调高来伤或给特定职业额外理想目标。

## 门禁和报告

命令非零退出表示标准场景±10%、中频承伤占比<20%、施法计划或积分账本验证失败。成功只代表明示标准通过；**必须阅读JSON/Markdown中的敏感性及三策略未达项**，不能把退出0等同于所有设计期望达成。

报告分别提供三个等级的总分/KDA偏差，以及①②相对③的KDA增幅、总分占比。已知当前版本：标准无词条英雄优先通过；清兵/词条场景有超±10%，部分职业不施法并非最高KDA，高频单重击在部分样本总分可超过中频循环。这些是未闭环项，后续不得抹去或伪称已经满足。

其他检查：`npm test`、`npm run build`；改积分显示时运行`tests/contribution.spec.js`与`tests/ranking.spec.js`。临时账号、截图和测试输出使用E盘辅助目录，必要时把`TEMP`、`TMP`、`MAGIC_QA_DIR`指向该目录。

当前规则与系数见仓库 `docs/rules/12-ratings-and-scores.md`、`shared/contribution-score.js`；源码优先于历史数值。防守方5体力契约未采纳；它会同时使总分+200、分母+2，不能只改分母，也不能借此宣称总分被压低。
