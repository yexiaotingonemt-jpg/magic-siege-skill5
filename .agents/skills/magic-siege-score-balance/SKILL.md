# 魔法王座技能与积分联调

适用于本项目的技能数值/机制、目标人数、冷却、费用、英雄面板/成长、契约或积分系数变更。纯美术、文案和布局调整不触发数值联调。用户当次明确要求优先于本 skill。

## 已确认的目标

- 玩家主要追求**总积分**；KDA只是实际消耗体力的效率。不能把“KDA更高但总分很低”直接判成刷总分漏洞。
- 同一标准场景，五职业在**5/20/40级、存活60秒、中频施法**下，总积分和KDA分别相对同级五职业算术平均偏差不超过 **±10%**。不能只对齐战士或只比较两个职业。
- 中频状态的**承伤积分 / 中频总积分 <20%**；分母包括体力基础分，不是“不施法总分/正常总分”，也不是承伤分/纯战斗分。它是标准场景校准目标，不是运行时20%硬截断。
- 中频参考为技能1/2/3/4各 **8/3/2/1次**；这是等待时机的校准计划，不是线上实测频率。不要把12/6/4/2的近冷却循环称作常态。技能要遵守实际合法目标、冷却和前摇，不强制花完体力。
- 当前标准基准为**无词条、英雄优先**；还必须报告清兵优先与合法词条样本的敏感性。不能把仅标准基准通过写成所有场景/所有构筑都平衡。

## 不得遗漏的规则

- 使用当前源码实际值：`shared/contribution-score.js`、`shared/config.js`及技能/词条实现。不要把历史报告的系数重新覆盖回来。
- 积分为有效伤害×a＋**原始承伤**×b＋有效治疗×c＋小兵击杀奖励＋英雄击杀×e＋英雄助攻×f＋**实际消耗体力×100**。契约也计；3点技能=300分，3点契约=300分。失败与补充体力不给分。
- 原始承伤在护甲、减伤、护盾结算前取值；伤害分为实际扣血+盾吸，不计过量；治疗只计实际恢复。承伤口径不因压低b而改成减伤后伤害。
- 小兵击杀奖励按最大生命折算，维持 `d=4000a`：满血M的小兵，纯补刀约aM，纯伤害aM，独自打满并击杀2aM。改a须同步检查d。2倍关系指战斗分；叠加固定体力分后总分不必严格2倍。
- 英雄助攻为死亡前5秒内直接有效伤害，或先有效治疗友军、该友军随后命中死者；**治疗与命中都须在死亡前5秒内**。不限最终击杀者，后治疗不追溯旧命中；同次去重、击杀者不重复拿助攻。按原英雄职业归属，死后窗口内仍可补计。
- 契约费用目前双方均3点。**防守方5点仅是讨论候选，尚未实施**；不能把举例视为已授权变更。费用一旦改变，总分及KDA分母都按实际扣除更新，双方费用不同时两个±10%指标必须独立验算。

## 调整时执行

1. 阅读项目 `AGENTS.md`、`CONTRIBUTING.md`、当前规则；涉及发布时继续遵守发布约定。用户授权技能修改时，在同次工作内同步调整积分，不要只改技能后留下未核对的积分系统；本 skill 不授予部署、发消息或改待定规则的权限。
2. 修改前记录基线，修改后运行 `npm run test:balance`。详细场景、命令和输出解释见 [基准说明](references/benchmark.md)。该永久测试组件读取当前引擎；辅助输出放到 `E:/Codex/Support/魔法王座`，不放KC数值源目录或C盘。
3. 检查三节点五职业标准总分/KDA及承伤占比；超标则联调a/b/c及必要的奖励项，再复跑。不能只调一个职业来掩盖其余职业之间本来已超标的差距，不能把每个节点独立换系数冒充固定系数平衡。
4. 同时比较①不施法但正常普攻、②只用最终KDA最高的技能、③中频正常使用。单技能必须四个都测试，注明次数/实际体力；另查按冷却高频单技能，不能把两种频率混在一张结论里。
5. 每个职业/等级都列总分、实际体力、KDA、①②相对③的KDA提高/降低百分比、总分占③百分比。用户期望少施法效率高但总分上不去；若顺序不符或单技能总分超过正常，明确列为未达项，不能预先写成①最高。KDA按整个策略选优，不等于技能自身直接贡献最高。
6. 对清兵、词条、群体目标、热量/持续效果等相关场景做敏感性验证；改费用还须查重契约/有限体力预算的影响。若改变解锁或冷却使中频计划不可行，明确报告并重建可比计划，不能静默少放技能后宣称原标准通过。
7. 做必要的逻辑测试、构建及积分UI验证，同步更新规则与结论。相互冲突的约束需给出证据和未达范围；不得靠提高固定体力分、截断报告、忽略过量/溢出或事后改验收口径制造通过。

## 输出与提交

给出最终系数、关键假设、三个等级结果、三策略差异和未达项；区分实测/引擎基准/解析重计价。仅总循环拟合接近不能证明策略平衡；受控存活依赖外部治疗不能当成实战生存能力。

变更结果默认留在本地；用户要求提交时按中文规范提交相关文件，保留其他并行修改。提交不是发布，未完成两端发布验证前不得报告上线。
